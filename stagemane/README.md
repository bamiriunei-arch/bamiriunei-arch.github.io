# ステマネ

演奏会の**司会原稿・進行表・タイムスケジュール**を、1つの入力から作るツールです。プログラム（影アナ・司会・曲・ト書き・休憩など）を順に入れると、3つの書類がその場でそろい、PDF にできます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/stagemane/

## できること

- **基本情報**：団体名・演奏会名・日付・会場・開場・開演・終演・版の表記・ロゴ、書類の体裁（司会原稿の文字の大きさ・作曲者を出すか・進行表の欄の名前など）
- **プログラム**：影アナ（ベルつき）・司会（だれが・どこで）・曲（作曲・編曲・指揮・演奏時間・メドレーの中の曲・アンコール）・ト書き（明転・奏者起立など）・部の見出し・休憩・節目。よく使う形はひな形から足せます
- **タイスケ**：当日の時刻ごとに、舞台・生徒・手伝いなどの列で、だれが何をするか
- **点検**：時間の目安（話す文の字数・曲の長さ・ト書きの時間から計算）と、抜け・書きかけ（【　】の空欄のまま・演奏時間がない・時刻の前後が逆・終演に間に合わない・基本情報とプログラムやタイスケの時刻のちがいなど）
- **仕上がり**：司会原稿・進行表・タイスケを A4 で見て、1つずつ、または3点まとめて PDF に
- **本番モード**：本番やリハーサルで、いまの項目と次のきっかけを大きく出します。押し・巻きを、本番の時刻か始めてからの経過時間で比べられます
- **データを書き出す・読み込む**：演奏会ごとのファイル（`{"app":"stagemane","concert":{…}}`）。ほかの端末に移すときや、コウバン・仕込み図・楽譜ライブラリに渡すときに使います

はじめて開いたときは、使い方を見るための例の演奏会が入っています（団体・指揮者・演奏会の名前は架空のものです）。上の「新規」で自分の演奏会を作り、来年の分は「複製」から作れます。

## ほかのツールとのつながり

- **楽屋の本番**：「基本情報」の「楽屋の本番」で、楽屋の「本番」とつなげられます（「＋ 楽屋の本番の一覧に入れる」で、ここの名前と日付の本番を楽屋に作ることも）。楽屋の本番を押すと、その本番の司会原稿・進行表を開くか作ります（作るときは、本番の名前・日付・会場・開演が入ります）
- **楽譜ライブラリの曲目一覧**：「プログラム」の「楽譜ライブラリの曲目一覧から曲を入れる」で、曲目一覧の曲（曲名・作曲者・編曲者・演奏時間・メドレーの曲）を、曲名が空の「曲」の札に順に入れます（足りなければ最後の曲のあとに足します）。楽屋の本番とつないだとき・楽屋の本番から作ったときに、その本番の曲目一覧があれば知らせます
- **コウバン・仕込み図・楽譜ライブラリ**：それぞれの「ステマネから」で、この端末のステマネの演奏会を、ファイルにしなくても選べます（曲の順番・きっかけ表・演奏の記録と曲目一覧）。ステマネで書き出したファイルからも選べます

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「データを書き出す」か、楽屋の「バックアップ」で保存してください（楽屋のバックアップにはステマネの演奏会も入ります）。
- このツールのデータのキーは `stagemane.v1`（演奏会の順番）と `stagemane.v1.c.〈演奏会のid〉`（演奏会ごと）です。楽屋に入れた部員・本番のデータ（`gakuya.org`）は、同じ場所（`bamiriunei-arch.github.io`）のツールどうしで共有します。
- PDF を作る道具（html2canvas・jsPDF）は、はじめて PDF を作るときに cdnjs から読み込みます。一度読んだあとは、この端末に保存しておくので、ネットがなくても PDF を作れます。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の「ステマネ」を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です（リポジトリのいちばん上の `node sync-common.js` でそろえます）。
このツールだけを直すときは、その外側（「ステマネだけの見た目」「ステマネ本体」）を直してください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `stagemane/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/stagemane/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `stagemane` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js stagemane
```

`tests/app.spec.js` がパソコンの幅（例の演奏会・楽屋の本番とのつながり・部員用の端末・書き出しと読み込み）、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
