# テンポマップ

練習番号ごとの小節数・拍子・テンポから演奏時間を計算し、コンクールなどのカット案を制限時間と比べるツールです。テンポや拍子の変化どおりに鳴る練習用クリックもあります。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/tempomap/

## できること

- **区間**：練習番号・小節数・拍子・拍の単位（四分・付点四分・八分など）・テンポ・終わりのテンポ（rit.・accel.）・ゆとり秒（フェルマータ・G.P.）・まとまり（7/8 の 2+2+3 など）・メモ
  - 時間の計算：小節数 × 1小節の拍数 × 60 ÷ テンポ。テンポが変わる区間は、拍ごとにまっすぐ変わるとして計算します
  - 6/8 を付点四分で数える、7/8 を八分で数える、なども正しく計算します
- **時間の帯**：区間の長さどおりの帯で、切る区間（斜線）と、制限に届く所（赤い線）が見えます
- **カット案**：案ごとの合計、同じ枠で計るほかの曲（課題曲など）をあわせた時間、制限時間との差、切る長さ
- **実測による補正**：本番やリハーサルで計った時間を入れると、計算とのずれ（伸び縮み）をほかの案にも当てて目安を出します
- **クリック**：はじめる小節・カット案・速さ（50〜120%）・1小節前からのカウント・裏拍（付点の拍は3つ）・区間のくり返し。小節の頭は高い音、まとまりの頭は中くらいの音
- **共有コード**：テンポマップを文字のかたまりにして送れます。公開ページでは、開くとそのまま読み込むリンクも作れます
- **印刷・書き出し**：テンポマップとカット案の比較（A4）、CSV、ファイルへのバックアップ
- **くり返し・D.S.・D.C.**：区間ごとの「くり返し（2〜4回）」と、D.S.・D.C.（to Coda・Fine）。「演奏の順番」で確かめられ、時間・帯・クリック・印刷がその順番になります（もどったあとは、くり返しはしません）
- **何小節目から分ける**：「2つに分ける」で、分ける小節を選べます（rit.・accel. の途中なら、分け目のテンポも出します）

## ほかのツールとのつながり

- **合奏ノート**：共有コード（同じ場所に置いていれば、テンポマップの曲そのもの）から、録音の小節の目印を作れます
- **楽屋**：新しい曲を作るとき、楽屋の曲（楽譜ライブラリで入れた曲）から選べます
- **ステマネ・楽譜ライブラリ**：計算した演奏時間をコピーして、「演奏時間」に貼れます

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」でバックアップしてください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `tempomap.` で始まります。
- 同じツールを2つのタブで開いて直したときは、あとから保存する方で「どちらを残すか」を聞きます（黙って上書きしません）。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります（アイコンは楽屋のもの） |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「テンポマップだけの見た目」「テンポマップ本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `tempomap/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/tempomap/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `tempomap` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js tempomap
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
