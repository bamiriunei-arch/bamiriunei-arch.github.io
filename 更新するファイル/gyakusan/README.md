# 本番逆算スケジュール

演奏会・コンクールの日付から、準備の締め切りを逆算して並べるツールです。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/gyakusan/

## できること

- **ひな形**：定期演奏会（ホール）・定期演奏会（大学）・学校行事・新入生歓迎・合宿・地域のイベント／依頼演奏・吹奏楽コンクール・アンサンブルコンテスト・空。日数はよくある目安なので、施設や大会のきまりに合わせて直してください
- **やること**：月ごとに、締め切り・あと何日／何日すぎ・担当・メモ。すんだらチェック。本番までの時間の帯（今日と締め切りの点）
- **締め切りの決め方**：本番の何日前か（本番の日を変えるといっしょに動く）、または決まった日。土日・祝日の締め切りは前の平日にそろえられます（日本の祝日・振替休日・国民の休日を計算）
- **使うツールへのリンク**：「司会原稿・進行表」→ステマネ、「パート割り」→コウバン、「ホールとの打合せ」→仕込み図、「楽器の運搬」→搬入出リスト、「会計の報告」→会計、「参加の申込み・出欠をとる」→出欠 など
- **自分のひな形**：今年のならびを保存して、来年の本番を作るときに選べます。本番を「来年用に複製」もできます
- **書き出し**：今週と来週のやることのコピー（LINEなどに貼れる）、全部のコピー、印刷・PDF、カレンダー（.ics：Googleカレンダー・iPhoneのカレンダーに入る）、CSV
- **新しいひな形**：学校行事（文化祭・式典）、新入生歓迎・部活動紹介、大学の定期演奏会（会場の抽選・広告集め・OB/OGへの案内・引き継ぎ）、合宿。団体の種類に合うひな形を上に出します
- **団体の種類に合わせる**：一般の団体・地域クラブは、はじめから「土日・祝日の締め切りを前の平日に」をしません。一般・大学では「保護者への案内」を「団員（部員）への案内」にします
- **見るだけのリンク・QR**：本番までのスケジュールを、係や保護者のスマホに配れます（担当でしぼって見られます）

## ほかのツールとのつながり

ひな形のやることから、楽屋シリーズの各ツールを開けます。

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」でバックアップしてください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `gyakusan.` で始まります。
- 同じツールを2つのタブで開いて直したときは、あとから保存する方で「どちらを残すか」を聞きます（黙って上書きしません）。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります（アイコンは楽屋のもの） |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「本番逆算スケジュールだけの見た目」「本番逆算スケジュール本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `gyakusan/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/gyakusan/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `gyakusan` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js gyakusan
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
