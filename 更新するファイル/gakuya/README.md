# 楽屋（がくや）

吹奏楽の団体のためのツール集「楽屋シリーズ」の入口です。
部員・曲・楽器のデータを楽屋に入れておくと、同じ場所（`bamiriunei-arch.github.io`）に置いた全部のツールで使えます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。AIは使っていません。

公開ページ：https://bamiriunei-arch.github.io/gakuya/

## 楽屋でできること

- **ツール**：楽屋シリーズと、ステマネ・バミリ・ドリルボードへの入口。この端末で使っているツールには、入っているデータの数が出ます。はじめて使うときは「はじめにやること」のチェックリストが出ます
- **部員（団員）**：名前・よみ・学年・いつもの楽器・持ち替え・状態（在籍・休部・引退・エキストラ・賛助・卒業）・役職・入団した年・メモ・指導者メモ。さがす・しぼる・並べ替え。まとめて入力・CSVの読み込み（Shift_JISのExcelも）は、足す前に確かめる表を出します。スマホでは1人1枚の札で出します
- **団体・年度**：団体の種類（中学校・高校・中高一貫・大学・一般・地域クラブ）、名前、名簿の年度、大学は引退の時期。種類で、学年の選び方・進級・呼び方（部員／団員、顧問／団長など）・ほかのツールのはじめの値が変わります
  - **進級**：何年度から何年度にするかを出して、全員の学年を1つ上げます。いちばん上の学年は卒業・退部に。同じ年度に2回進級させそうなときは確かめます
  - **引退**：学年ごとに引退にできます（在籍にもどすこともできます）
  - **この端末の団体**：学校の部と地域クラブのように、いくつかの団体のデータを切りかえて使えます
- **つながり**：どのツールがデータを入れて、どのツールが使うか
- **バックアップ**：楽屋シリーズとバミリ・ドリルボードのデータ（楽器台帳の写真も）を1つのファイルにまとめ、戻せます。引き継ぎファイル（次の人へのメモつき）と、引き継ぎのしおりの印刷。保存している量も出ます
- **表示**：文字を大きくする（この端末の全部のツール）。ホーム画面に追加すると、どのツールから追加しても「楽屋」という1つのアプリになります

## 楽屋シリーズ

| ツール | フォルダ | できること |
| --- | --- | --- |
| 楽屋 | `gakuya` | 入口・部員・団体と年度・バックアップ・引き継ぎ |
| 本番逆算 | `gyakusan` | 本番の日から準備の締め切りを逆算。見るだけのリンク |
| 楽譜ライブラリ | `gakufu` | 所蔵楽譜の台帳、パート譜の欠け、レンタル期限、貸し借り、演奏の記録、今の部員でできる曲、著作権の手続き用の曲目一覧 |
| テンポマップ | `tempomap` | 演奏時間の計算（くり返し・D.S.も）、カット案と制限時間、練習用クリック |
| コウバン | `kouban` | 香盤表（曲ごとのパート割り）。見るだけのリンクで自分の出番 |
| 楽器決め・編成計画 | `gakkigime` | 新入部員の楽器の割り振り案、来年・再来年のパートの人数（一般の団体は欠員と募集） |
| 仕込み図 | `shikomi` | 音響・照明の打合せ資料 |
| 楽器台帳 | `gakki` | 楽器・備品・消耗品、今年度の使う人、修理・貸し出しの記録、資産台帳、QRラベル |
| 搬入出リスト | `hannyu` | 楽器運搬の積み込みとチェック。見るだけのリンクで運ぶ人もチェック |
| 合奏ノート | `gassou` | 合奏ごとに自由に書けるノート、録音に小節の目印とコメント |
| 出欠 | `shukketsu` | 練習・本番ごとの出欠、だれもいないパート、出席率、返事の取り込み |
| 会計 | `kaikei` | 団費の集金、帳簿、予算と実績、会計報告 |

前からあるツール：ステマネ（演奏会の資料）、バミリ（`bamiri`・配置図）、ドリルボード（`drillboard`・マーチング）。

## しくみ

### 1つずつ独立している

全部のツールを、1つのリポジトリ `bamiriunei-arch.github.io` に入れています。フォルダ1つがツール1つです。
どのツールも、そのフォルダの `index.html` 1つで動き、ほかのフォルダのファイルを読み込みません（ホーム画面のアイコンだけは、楽屋のものを使います）。どれか1つを直しても、ほかに影響しません。
それぞれのフォルダに、説明書（`README.md`）・自動テスト（`tests/`）・ホーム画面用の設定とオフライン用の `sw.js` が入っています。自動テストは、GitHub に上げるたびに全ツール分が動きます。

### 共通部品

各 `index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分は、全ツールで同じ内容です（見た目と、データの読み書き・2つのタブの見張り・ファイル保存・印刷とPDF・CSV（Shift_JISも）・名簿の読み取り・パートの名前のそろえ方・見るだけのリンクとQRなど）。
1つのツールだけを直すときは、その外側だけを直します。共通部品を変えるときは、楽屋（`gakuya/index.html`）で直してから、リポジトリのいちばん上で `node sync-common.js` を動かすと、全ツールにそろえて写せます。変えたら `GKY.VERSION` を上げてください。

### 楽屋のデータ（全ツールで共有）

同じ場所に置いたツールは、ブラウザの `localStorage` の `gakuya.org` を共有します。中身はこの形です。

```json
{
  "app": "gakuya", "format": 1,
  "org": { "name": "団体の名前", "year": 2026, "type": "chu", "retire": "", "promoted": { "to": 2026, "at": "2026-04-01" } },
  "members": [ { "id": "m…", "name": "山田 花子", "kana": "", "grade": "中2", "part": "Cl", "subs": ["B.Cl"], "status": "active", "active": true,
                 "roles": ["パートリーダー"], "joined": null, "note": "", "staffNote": "" } ],
  "songs": [ { "id": "s…", "title": "曲名", "kana": "", "composer": "", "arranger": "", "publisher": "", "dur": 360, "parts": ["Fl1", "Cl1", "Cl1"], "opt": ["Ob"] } ],
  "instruments": [ { "id": "g…", "no": "Cl-01", "name": "B♭クラリネット", "part": "Cl", "owner": "学校", "state": "使える", "user": "山田 花子", "usable": true } ],
  "updated": { "org": 0, "members": 0, "songs": 0, "instruments": 0 }
}
```

- `org.type`：`chu` 中学校・`koko` 高校・`chuko` 中高一貫・`daigaku` 大学・`ippan` 一般・`chiiki` 地域クラブ（空は「まだ選んでいない」）。`retire` は大学の引退の時期（`大3`・`大4`）。`promoted` は最後に進級させた年度
- `members[].status`：`active` 在籍・`leave` 休部（休団）・`retired` 引退・`extra` エキストラ・`support` 賛助・OB/OG・`gone` 卒業・退部。`active`（true/false）は、演奏する人（在籍・エキストラ・賛助）かどうかで、前の版のツールのために残しています
- `members[].joined` は入団（入部）した年、`staffNote` は顧問・指導者だけのメモ（ファイルに入れるかどうかを選べます）
- `songs[].opt` は「なくても演奏できる」パート
- `members` は楽屋（と楽器決めの「楽屋の部員に足す」）が書きます。`songs` は楽譜ライブラリ、`instruments` は楽器台帳が書きます。ほかのツールは読むだけです。書くツールは、自分の区分だけを書きかえます

パートは、バミリの奏者ラベルと同じ書き方（`Fl`・`Cl1`・`A.Sax`・`Tp`・`Hn`・`Euph`・`Tuba`・`S.D.`・`Timp` など）にそろえています。「クラリネット」「ラッパ」「パーカス」「コンバス」なども読み込むときに記号に直します。

### ファイル・リンクでのつながり

- ステマネで保存した演奏会のファイル（`{"app":"stagemane","concert":{…}}`）→ コウバン（曲の順番）、仕込み図（きっかけ表）、楽譜ライブラリ（演奏の記録・曲目一覧）
- バミリで保存した配置図のファイル（`{"W":…,"D":…,"items":[…]}`）→ コウバン（席に名前を入れて返す）、仕込み図（下絵）、搬入出リスト（運ぶもの）
- テンポマップの共有コード（`TMZ…`）→ 合奏ノート（小節の目印。くり返し・D.S. も）
- 見るだけのリンク（アドレスの `#v=…`）：コウバン・搬入出リスト・本番逆算・出欠。中身はリンクの中だけにあり、どこのサーバーにも送られません

### Claude の画面の中で開いたとき

Claude のアーティファクトとして開いたときは、ツールごとに別の場所として開くので、楽屋のデータは共有されません。ファイルの保存は確認の画面を通り、印刷は「PDFで保存」になります。ふだん使うときは、公開ページで開いてください。

## GitHub Pages への置き方（はじめの1回）

楽屋の画面では、アドレスに `?dev` をつけたときだけ「置き方」のタブが出ます。手順は次のとおりです。

1. GitHub（bamiriunei-arch）で「New repository」を押し、名前を `bamiriunei-arch.github.io`（このとおり）にして、**Public** で作ります
2. 「uploading an existing file」を押し、配ったフォルダの中身を入れて「Commit changes」。1回に上げられるのは100ファイルまでなので、ツールのフォルダをいくつかずつに分けて上げます
3. 自動テストの設定 `.github/workflows/test.yml` は、「Add file」→「Create new file」で名前に `.github/workflows/test.yml` と入れ、中身を貼って作るのが確実です（フォルダの名前が `.` で始まるため、画面から上げると入らないことがあります）
4. 「Settings」→「Pages」で、Branch が `main`・フォルダが `/ (root)` になっているか確かめます
5. 数分すると `https://bamiriunei-arch.github.io/gakuya/` で楽屋が開けます。「Actions」タブで「自動テスト」に緑のチェック（✓）が付けば、正しく動いています

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「まとめてバックアップ」で保存してください（最後に保存してから日がたつと、ツールの画面でお知らせします）。学校のChromebook・iPadは、サインアウトでデータが消える設定のこともあります。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `gakuya.` で始まります。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ホーム画面に追加したとき・ネットがないときに開けるようにする |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「楽屋だけの見た目」「楽屋本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `gakuya/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/gakuya/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `gakuya` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js gakuya
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）、`tests/standalone.spec.js` がホーム画面のアプリの中での動きのテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
