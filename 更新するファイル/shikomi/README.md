# 仕込み図

演奏会の音響・照明の打合せ資料を作るツールです。使うもの（司会・ソロ・ベース・録音など）を選ぶとインプットリストができ、配置図の上にマイクや電源を置いた仕込み図と、きっかけ表を、まとめて印刷できます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/shikomi/

## できること

- **使うもの**：司会（ワイヤレス・有線）、影アナ、指揮者のお話、ソロ、歌、エレキベース、キーボード、エレキギター、ドラムセット、音源の再生、録音（ホールに頼む・持ち込み）、吊りマイク
- **インプットリスト**：ch番号・音源・マイクや機材・スタンド・ファンタム電源（いる／いらない／？）・位置・メモ。入れた数（ワイヤレス・DI・ファンタム）を数えます
- **仕込み図**：配置図の上に、ch番号つきの印・モニター・スピーカー・電源・ピンスポットの位置・メモを置いて、指でずらせます（下が客席、左が下手、右が上手）
- **きっかけ表**：本番の流れにそって、音響・照明・舞台のきっかけ。部の見出しも入れられます
- **お願いしたいこと**：選んだものから、打合せで確かめることの一覧を作ります（ピンスポット、電源、録音の受け取り方など）
- **印刷・PDF**：打合せシート・インプットリスト・仕込み図・きっかけ表を1つの資料に

機材の名前は一般的な例です。ホールによって常設の機材や持ち込みのきまりが違うので、最後はホールの担当の方と相談して決めてください。
- **用紙**：印刷のときに A4・B4・A3 を選べます

## ほかのツールとのつながり

- **バミリ**：保存した配置図のファイル（同じ場所に置いていれば、バミリで開いている配置図）を、仕込み図の下絵にできます
- **ステマネ**：保存した演奏会のファイルから、きっかけ表を作れます。影アナ・司会・曲・ト書き・休憩の順に並び、進行表の「照明」「舞台」のメモも入ります

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」でバックアップしてください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `shikomi.` で始まります。
- 同じツールを2つのタブで開いて直したときは、あとから保存する方で「どちらを残すか」を聞きます（黙って上書きしません）。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります（アイコンは楽屋のもの） |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「仕込み図だけの見た目」「仕込み図本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `shikomi/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/shikomi/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `shikomi` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js shikomi
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
