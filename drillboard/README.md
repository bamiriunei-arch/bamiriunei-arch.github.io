# ドリルボード

マーチングのドリル（隊形と動き）を作る・見る・練習するためのアプリです。楽屋シリーズの1つです。
`index.html` 1つで動き、作ったショーは使う人のブラウザの中に保存されます（どこのサーバーにも送られません）。

公開しているページ：https://bamiriunei-arch.github.io/drillboard/

前は別のリポジトリ（`drillboard`）に置いていましたが、v14 から楽屋シリーズのリポジトリ `bamiriunei-arch.github.io` の `drillboard/` フォルダに移しました。
公開ページのURLと、保存の場所（`drillboard.v1` など）は同じなので、今までのショー・音源・設定はそのまま使えます。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ホーム画面に追加したとき・ネットがないときに開けるようにする（ホーム画面では「楽屋」のアプリの中で開きます） |
| `audio/`（使うときだけ作る） | 音源ファイルの置き場所。アプリの「音源のURL」に `audio/曲名.mp3` と書くと、リンクやQRで開いた人もここから聞けます |
| `shows/`（使うときだけ作る） | 「サイトに置いて配る」で保存したショーのファイルの置き場所。`?show=shows/名前.txt` の短いリンク・QRで開けます |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定（テストの道具は、リポジトリのいちばん上の `package.json`） |

## 楽屋シリーズとつなぐ

ドリルボードは、楽屋シリーズ（https://bamiriunei-arch.github.io/gakuya/ ）の1つなので、同じ端末のブラウザの中で、次のものを使えます。

- **楽屋へのボタン**：画面の右上の「楽屋」で、楽屋（ツールの一覧）に戻れます

- **楽屋の部員**：「隊員」→「名簿を貼り付けてまとめて追加」→「楽屋の部員を入れる」で、楽屋に入れた部員（在籍・エキストラ・賛助）の名前とパートを名簿の欄に入れます（名字だけでも入れられます）。名前をつけた隊員は、「全員のリンク一覧」で一人ずつのリンクを配れます
- **ファイル置き場の録音**：「音源」→「入っている録音から」で、テンポマップで録った通しや、合奏ノートで開いた録音を、曲の音源に選べます。ドリルボードで選んだ音源もファイル置き場に入るので、合奏ノートなどから選べます
- **バックアップ・同期ファイル**：楽屋の「バックアップ」に、ドリルボードのショーも入ります

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」は、楽屋シリーズの全ツールで同じ内容です（`GKY`）。部員とファイル置き場は、この共通部品（`GKY.org`・`GKY.media`）で読み書きします。
「共通部品の見た目を元に戻す」の部分は、共通部品の見た目がドリルボードの画面にかからないようにするもので、`node sync-common.js` が作ります（手で直さないでください）。

どちらも端末の中だけで使い、どこのサーバーにも送りません。

`audio/` と `shows/` に置いたファイルは、場所（URL）を知っている人ならだれでも開けます（公開リポジトリのとき）。
音源は、置いてよいもの（自分たちの録音など）かを確かめてから置いてください。

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります。
版を上げると、前の版を使っていた人には「ドリルボードが新しくなりました」と更新内容が出ます。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `drillboard/` フォルダです。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `drillboard` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、どのテストが失敗したかをクリックして見られます（失敗の記録は「Artifacts」の `playwright-report` からダウンロードできます）

## 自動テスト

`tests/` の中に、だいたい次のことを調べるテストがあります。

- 起動してエラーが出ない・はじめての人に「ようこそ」が出る・「3分で1セット」のガイドが最後まで進む
- 隊員を足す → 形を作る → セットを足す → 再生 → 元に戻す
- 保存データ（共有リンク・ファイル）を書き出して読み直しても同じになる（メモ・版・ルール込み）
- 共有リンクの「同じ版・新しい版・古い版」の知らせ、自分用リンク（`&me=`）、自動バックアップ
- 練習の道具（速さ・区間ループ・カウントイン・1カウントずつ・演奏者の向き・大画面・2本指の拡大）
- ドリルの道具（自動割り当て・接触の直し方・間隔・左右対称・大会のルール）
- 印刷・PDF（コンテ・ドットシート）
- 動きの計算が前と同じか（`tests/fixtures/motion-golden.json` と比べる）
- 音源（この端末に覚える・音源のURL・音源込みのファイル・カウントインの前の小節・小節の頭／裏拍のクリック）。テスト用の音は `tests/fixtures/click120.wav`
- v10 の道具（ベルフロント・メモのセット選び・半歩ずらす案・歩幅のばらつき・パートまとめのドットシート・全員のリンク一覧・コンテのQR・大会のルール・`?show=` で開く）
- 楽屋シリーズに入れたところ（楽屋へのボタン・Googleなど外へ送らない）
- v13 の道具（楽屋の部員を隊員にする・ファイル置き場の録音を音源にする・選んだ音源をファイル置き場に入れる）
- v11 の道具（ゲートターン・平行四辺形・形をくり返して並べる）と、動画から隊形を拾う機能（線に合わせる・人を見つける・セットにする・続けて拾う・まとめる）。テスト用の動画 `tests/fixtures/floor_test.webm`（カメラが動かない）と `tests/fixtures/zoom_test.webm`（定点カメラでズームする）は、同じフォルダの `make_floor_test.py`・`make_zoom_test.py` で作った絵の動画です（本物の大会の動画は入れていません）

### 自分のパソコンで動かすとき（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js drillboard
```

動きの計算をわざと変えたときは、`drillboard` フォルダの中で答えを作り直します：`UPDATE_GOLDEN=1 npx playwright test tests/motion.spec.js`

テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__db` から触っています。
ふだんの使い方（`?test` なし）では何も変わりません。

## 変更の記録（GitHub Desktop のすすめ）

ブラウザから「Add files via upload」で上げると、記録の名前がいつも「Add files via upload」になり、あとから「どの版で何を変えたか」がわかりにくくなります。
GitHub Desktop（無料）を使うと、次のようにできます。

1. GitHub Desktop を入れて、GitHub のアカウントでログイン
2. 「Clone a repository」で `bamiriunei-arch.github.io` を選び、パソコンの中にフォルダを作る
3. 新しい `index.html` を、そのフォルダの `drillboard/index.html` に上書きする
4. GitHub Desktop の左下の「Summary」に、何を変えたか書く（例：「ドリルボード v12：定点カメラ（ズームあり）の動画に対応」）
5. 「Commit to main」→ 右上の「Push origin」

こうしておくと「History」タブで、いつ・何を変えたかが一覧で見られ、まちがえたときも「Revert」で前の版に戻せます。

`.github` のように「.」で始まるフォルダは、ブラウザからのアップロードでは見えないことがあります。
そのときは GitHub の画面で「Add file」→「Create new file」を押し、名前の欄に `.github/workflows/test.yml` と打って、中身を貼り付けて保存してください。
