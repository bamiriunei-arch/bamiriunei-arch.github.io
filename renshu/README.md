# 練習計画

出欠の練習の日ごとに、何を練習するか（曲・練習番号と小節・パート・合奏やパート練習などの形）を決めて、タイムテーブルにするツールです。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/renshu/

## できること

- **練習の日**：出欠の予定（練習）を、月ごとに並べます。「＋ 練習の日を足す」で足した日・「日時・場所を直す」で直した日は、出欠の予定にも入ります（「毎週くり返して足す」・祝日をのぞく、もあります）
- **メニュー**：その日にすることを、上から順に入れます。形（基礎合奏・合奏・分奏・パート練習・個人練習・通し・休憩・その他）、曲（楽屋の曲）、練習番号・小節（テンポマップの区間から選べる）、パート、何分、メモ。前の練習日のメニューを写せます
- **タイムテーブル**：はじまりの時刻から、メニューの分を順に積んだ時刻を出します。練習の時間（はじまり〜おわり）をこえると知らせ、こえた日の数をタブに出します
- **本番から下書き**：楽屋の本番を選ぶと、その本番の曲（楽譜ライブラリの曲目一覧、なければコウバンの曲）を、本番までの練習の日に「譜読み（35%）→ 区間（40%）→ 通し → ゲネプロ（最後の1回）」の順で割り振った下書きを作ります。区間は、テンポマップの練習番号を2〜3つずつまとめたものです。決まった手順なので、同じ入力なら同じ下書きになります。メニューが入っている日は、選ばなければ作り直しません
- **配る**：見るだけのリンク・QR（日ごとのメニューとタイムテーブル）、文でコピー（LINE などに貼る）。期間は2週間・1か月・2か月・これからの本番まで
- **印刷・カレンダー**：日ごとのタイムテーブルの印刷・PDF、練習の日をメニューつきの予定にしたカレンダー（.ics）

## ほかのツールとのつながり

- **出欠**：練習の日は、出欠の予定（種類が「練習」「その他」のもの）です。出欠が例のデータのときは使いません。ここで練習の日を足すと、出欠の例のデータは消えて、新しい予定が入ります
- **楽屋の曲**：メニューの「曲」は楽屋の曲（楽譜ライブラリで入れた曲）から選びます。パートの候補は、その曲の編成から出します
- **テンポマップ**：曲名が同じテンポマップの区間（練習番号と小節）を、「練習番号・小節」の候補に出します
- **楽譜ライブラリ・コウバン**：本番の曲は、その本番につないだ楽譜ライブラリの曲目一覧（なければ同じ日付の曲目一覧）、なければコウバンの曲から読みます
- **楽屋の本番**：楽屋の「本番」から開くと、その本番の下書きの画面になります。下書きを作った本番は、楽屋の本番の「ツールごとの記録」に出ます
- **部員用の端末**：部員用の端末では、出欠の予定を書きかえません

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」か、楽屋の「まとめてバックアップ」で保存してください。
- このツール自身のデータのキーは `renshu.` で始まります（日ごとのメニューは、出欠の予定の id でつないでいます）。練習の日そのもの（日付・時刻・場所）は出欠のデータ（`shukketsu.v1`）です。
- 同じツールを2つのタブで開いて直したときは、あとから保存する方で「どちらを残すか」を聞きます（黙って上書きしません）。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります（アイコンは楽屋のもの） |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「練習計画だけの見た目」「練習計画本体」）を直してください。
共通部品を変えるときは、楽屋で直してから `node sync-common.js` で全ツールにそろえ、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `renshu/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/renshu/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `renshu` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js renshu
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
