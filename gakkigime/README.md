# 楽器決め・編成計画

新入部員の楽器を、希望・体験での見立て・募集人数から割り振る**案**を出すツールです。案には一人ずつ理由がつくので、本人や保護者への説明に使えます。
今の学年ごとの人数から、来年・再来年のパートの人数を予測して、勧誘で力を入れるパートも見つけます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。AIは使わず、決まった手順で計算します（同じ入力なら同じ答え）。

公開ページ：https://bamiriunei-arch.github.io/gakkigime/

## できること

- **募集する人数**：パートごと。編成計画の「来年に足りない人数」をそのまま入れることもできます
- **新入部員の希望**：第1〜第3希望、体験で「向いていそう」と見た楽器、もう決まっている楽器、メモ。まとめて入力・CSVの読み込みもできます（「クラ」「ラッパ」なども読めます）
- **割り振りの案（3つ）**
  - 案A 希望を大事に：第1希望の人を多く
  - 案B 見立てを大事に：向いていそうな楽器を重く
  - 案C 全員を第2希望までに：第3希望や希望外を減らす
  - 計算のしかた：希望の順位と見立ての点数の合計が、全体でいちばん高くなる組み合わせを、定員を守って選びます（最小費用流という決まった手順）
- **理由**：「第2希望です。第1希望のフルートは、募集2人に第1希望が3人」のように出ます
- **決める**：案を選んで決めると、編成計画に入り、楽屋の部員に足すこともできます
- **編成計画**：今の1・2・3年の人数、来年（今の3年が引退）、再来年、毎年入る見込み、目安の人数。目安より少ないパートに ▼、今が3年生だけのパートに「3年のみ」
- **印刷・コピー**：割り振りの案（理由つき）、決まった楽器の一覧、勧誘で力を入れるパート、編成計画

## ほかのツールとのつながり

- **楽屋**：編成計画の「今の人数」を楽屋の部員（学年とパート）から数えられます。決まった新入部員を楽屋の部員に足せます

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」でバックアップしてください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `gakkigime.` で始まります。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ホーム画面に追加したとき・ネットがないときに開けるようにする |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「楽器決め・編成計画だけの見た目」「楽器決め・編成計画本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `gakkigime/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/gakkigime/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `gakkigime` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js gakkigime
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
