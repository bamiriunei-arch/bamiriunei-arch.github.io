# 楽屋（がくや）

吹奏楽の団体のためのツール集「楽屋シリーズ」の入口です。
部員・曲・楽器のデータを楽屋に入れておくと、同じ場所（`bamiriunei-arch.github.io`）に置いた全部のツールで使えます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。AIは使っていません。

公開ページ：https://bamiriunei-arch.github.io/gakuya/

## 楽屋でできること

- **ツール**：楽屋シリーズと、ステマネ・バミリ・ドリルボードへの入口。この端末で使っているツールには、入っているデータの数が出ます
- **部員**：名前・よみ・学年・いつもの楽器・持ち替えできる楽器・メモ・在籍。まとめて入力、CSVの読み込み・保存（Excelの名簿から）
- **団体・年度**：団体の名前（印刷物の下に入ります）と年度。年度がかわったら「進級させる」で全員の学年を上げ、中3・高3は「在籍していない」にします
- **つながり**：どのツールがデータを入れて、どのツールが使うか
- **バックアップ**：楽屋シリーズとバミリ・ドリルボードのデータ（楽器台帳の写真も）を1つのファイルにまとめ、戻せます
- **置き方**：GitHub Pages への置き方（全部を1つのリポジトリ `bamiriunei-arch.github.io` に入れる）と、フォルダと公開ページの一覧

## 楽屋シリーズ

| ツール | フォルダ | できること |
| --- | --- | --- |
| 楽屋 | `gakuya` | 入口・部員・バックアップ |
| 本番逆算 | `gyakusan` | 本番の日から準備の締め切りを逆算 |
| 楽譜ライブラリ | `gakufu` | 所蔵楽譜の台帳、パート譜の欠け、レンタル期限、演奏の記録、今の部員でできる曲 |
| テンポマップ | `tempomap` | 演奏時間の計算、カット案と制限時間、練習用クリック |
| コウバン | `kouban` | 香盤表（曲ごとのパート割り） |
| 楽器決め・編成計画 | `gakkigime` | 新入部員の楽器の割り振り案、来年・再来年のパートの人数 |
| 仕込み図 | `shikomi` | 音響・照明の打合せ資料 |
| 楽器台帳 | `gakki` | 楽器・備品・消耗品、修理・貸し出しの記録、QRラベル |
| 搬入出リスト | `hannyu` | 楽器運搬の積み込みとチェック |
| 合奏ノート | `gassou` | 合奏ごとに自由に書けるノート、録音に小節の目印とコメント |

前からあるツール：ステマネ（演奏会の資料）、バミリ（`bamiri`・配置図）、ドリルボード（`drillboard`・マーチング）。

## しくみ

### 1つずつ独立している

全部のツールを、1つのリポジトリ `bamiriunei-arch.github.io` に入れています。フォルダ1つがツール1つです。
どのツールも、そのフォルダの `index.html` 1つで動き、ほかのフォルダのファイルを読み込みません。どれか1つを直しても、ほかに影響しません。
それぞれのフォルダに、説明書（`README.md`）・自動テスト（`tests/`）・ホーム画面用のアイコンとオフライン用の `sw.js` が入っています。自動テストは、GitHub に上げるたびに全ツール分が動きます。

### 共通部品

各 `index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分は、全ツールで同じ内容です（見た目と、データの読み書き・ファイル保存・印刷とPDF・CSV・パートの名前のそろえ方など）。
1つのツールだけを直すときは、その外側だけを直します。共通部品を変えるときは、全ツールで同じに変えて `GKY.VERSION` を上げてください。

### 楽屋のデータ（全ツールで共有）

同じ場所に置いたツールは、ブラウザの `localStorage` の `gakuya.org` を共有します。中身はこの形です。

```json
{
  "app": "gakuya", "format": 1,
  "org": { "name": "団体の名前", "year": 2026 },
  "members": [ { "id": "m…", "name": "山田 花子", "kana": "", "grade": "中2", "part": "Cl", "subs": ["B.Cl"], "note": "", "active": true } ],
  "songs": [ { "id": "s…", "title": "曲名", "kana": "", "composer": "", "arranger": "", "publisher": "", "dur": 360, "parts": ["Fl1", "Cl1", "Cl1"] } ],
  "instruments": [ { "id": "g…", "no": "Cl-01", "name": "B♭クラリネット", "part": "Cl", "owner": "学校", "state": "使える" } ],
  "updated": { "org": 0, "members": 0, "songs": 0, "instruments": 0 }
}
```

- `members` は楽屋（と楽器決めの「楽屋の部員に足す」）が書きます
- `songs` は楽譜ライブラリが書きます
- `instruments` は楽器台帳が書きます
- ほかのツールは読むだけです。書くツールは、自分の区分だけを書きかえます

パートは、バミリの奏者ラベルと同じ書き方（`Fl`・`Cl1`・`A.Sax`・`Tp`・`Hn`・`Euph`・`Tuba`・`S.D.`・`Timp` など）にそろえています。「クラリネット」「ラッパ」なども読み込むときに記号に直します。

### ツールごとのデータ

| ツール | localStorage のキー |
| --- | --- |
| コウバン | `kouban.v1` |
| 楽譜ライブラリ | `gakufu.v1` |
| テンポマップ | `tempomap.v1` |
| 仕込み図 | `shikomi.v1` |
| 楽器台帳 | `gakki.v1`（写真は IndexedDB の `gakki`） |
| 楽器決め・編成計画 | `gakkigime.v1` |
| 搬入出リスト | `hannyu.v1` |
| 合奏ノート | `gassou.v1` |
| 本番逆算 | `gyakusan.v1` |

### ファイルでのつながり

- ステマネで保存した演奏会のファイル（`{"app":"stagemane","concert":{…}}`）→ コウバン（曲の順番）、仕込み図（きっかけ表）、楽譜ライブラリ（演奏の記録・曲目一覧）
- バミリで保存した配置図のファイル（`{"W":…,"D":…,"items":[…]}`）→ コウバン（席に名前を入れて返す）、仕込み図（下絵）、搬入出リスト（運ぶもの）
- テンポマップの共有コード（`TMZ…`）→ 合奏ノート（小節の目印）

### Claude の画面の中で開いたとき

Claude のアーティファクトとして開いたときは、ツールごとに別の場所として開くので、楽屋のデータは共有されません。ファイルの保存は確認の画面を通り、印刷は「PDFで保存」になります。ふだん使うときは、公開ページで開いてください。

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」でバックアップしてください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `gakuya.` で始まります。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ホーム画面に追加したとき・ネットがないときに開けるようにする |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「楽屋だけの見た目」「楽屋本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `gakuya/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/gakuya/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `gakuya` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js gakuya
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
