# 楽屋（がくや）

吹奏楽の団体のためのツール集「楽屋シリーズ」の入口です。
部員・曲・楽器のデータを楽屋に入れておくと、同じ場所（`bamiriunei-arch.github.io`）に置いた全部のツールで使えます。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。AIは使っていません。

公開ページ：https://bamiriunei-arch.github.io/gakuya/

## 楽屋でできること

- **ツール**：楽屋シリーズ（バミリ・ドリルボードも）への入口。この端末で使っているツールには、入っているデータの数が出ます。はじめて使うときは「はじめにやること」のチェックリストが出ます。下に、ご意見・アンケートのフォーム（バミリと同じ）があります
- **本番**：演奏会・コンクール・行事の一覧を、月ごと・年度ごと（4月はじめか1月はじめ）・カレンダーで見られます。本番を押すと、その本番の準備のスケジュール（本番逆算）・香盤表（コウバン）・曲目一覧（楽譜ライブラリ）・司会原稿と進行表（ステマネ）・音響照明の資料（仕込み図）・積み込み（搬入出リスト）・出欠・練習計画・予算（会計）を、まとめて開くか作れます。ほかのツールにある本番を見つけて入れる・印刷・カレンダー（.ics）・CSV・見るだけのリンクもあります
  - **当日の案内**：本番ごとに、集合・解散・タイムテーブル・持ち物・服装・担当（係）・当日の連絡先・ほかに伝えることを1つの画面にまとめます。本番の種類ごとのひな形と、つないだステマネのタイスケ（生徒・部員の列）から入れられます。部員にはリンク（QRコード）で配れ、部員用の設定リンクにも入ります。当日は今の時刻の行に印がつき、持ち物はチェックできます（チェックはその端末だけ）。前の日と当日は、ツールのタブの「次の本番」に「当日の画面」のボタンが出ます。印刷もできます
- **カレンダー**：1年（年度）の12か月を1画面で見渡し、選んだ月の大きな表と予定の一覧も出します。本番・練習と予定（出欠）・練習計画（その日の段階と曲）・準備の締め切り（本番逆算）・行事と休みを、選んで重ねられます。日を押すと、その日の予定（練習計画のある日は「練習計画で開く」）。1年を1枚・1か月を1ページの印刷、カレンダー（.ics）
  - **行事・休み**：定期テスト・長期休み・学校行事・部活動停止などを、期間つきで入れられます。カレンダーに色の帯で出て、印刷・.ics・部員用の設定リンク（本番の予定を見る）にも入ります
- **部員（団員）**：名前・よみ・学年・いつもの楽器・持ち替え・状態（在籍・仮引退・休部・引退・エキストラ・賛助・卒業）・役職・入団した年・メモ・指導者メモ。さがす・しぼる・並べ替え。まとめて入力・CSVの読み込み（Shift_JISのExcelも）は、足す前に確かめる表を出します（先に楽器・学年・状態を選んでおける・チェックした行をまとめてそろえる）。「えらんでまとめて変える」で、学年・楽器・状態・役職を何人分もまとめて変えられます。スマホでは1人1枚の札で出します
- **団体・年度**：団体の種類（中学校・高校・中高一貫・大学・一般・地域クラブ）、名前、名簿の年度、大学は引退の時期。種類で、学年の選び方・進級・呼び方（部員／団員、顧問／団長など）・ほかのツールのはじめの値が変わります
  - **進級**：何年度から何年度にするかを出して、全員の学年を1つ上げます。いちばん上の学年は卒業・退部に。同じ年度に2回進級させそうなときは確かめます
  - **引退・仮引退**：学年ごとに引退・仮引退にできます（在籍にもどすこともできます）
  - **この端末の団体**：学校の部と地域クラブのように、いくつかの団体のデータを切りかえて使えます
  - **年度末・年度はじめにやること**：バックアップ → 会計報告 → 譜面の回収と借りた楽譜の返却 → 楽器の点検と使う人 → 引退 → 進級 → 次の年度の本番 → 新しい部員の楽器決め → 部員用の設定リンク → 引き継ぎ、を順に案内します（一般の団体では、引退・進級・楽器決めは出ません）。済んだものにチェックを入れ、バックアップ・進級・次の年度の本番は自動で分かります。2月なかば〜4月は、ツールのタブの上でも知らせます（「今年は出さない」もできます）。どの年度のリストかは「いまの名簿の年度」で決まり（入れていなければ今日の日付から）、進級したばかりのときは進級の前の年度のまま続けます
  - **代表者・顧問用と部員用**：部員の端末で使うツールと、できること（本番の予定を見る・名簿を見る・合奏ノートを提出する・曲の一覧を使う）を団体ごとに決め、「部員用の設定リンク」（QRコード）で配ります。開いた端末は「部員用」になり、決めたツールのほかは開かず、楽屋のデータを書きかえません。部員用の端末の画面には「代表者・顧問用にもどす」と「この端末の団体」がなく、データをすべて消しても・バックアップや楽屋のデータを読み込んでも部員用のままです（見せる画面を分けるためのしくみで、パスワードのような守りではありません。ブラウザの設定でサイトのデータを消すと、はじめの状態にもどります）
- **お知らせ**：保護者向けの手紙・連絡。送迎のお願い・当番のお知らせ・集金のお知らせ（会計の集金から作れます）・ふつうのお知らせ。本番を選ぶと、日付・会場と「当日の案内」の集合・解散が入ります。あて先・差出人・本文・表・返事の締め切り・返事の欄の項目を直せ、返事の切り取り欄つきで印刷、見るだけのリンク、文でコピー（LINEなどに貼る）ができます。一般の団体では、あて先のはじめの値が「団員の皆様」になります
- **つながり**：どのツールがデータを入れて、どのツールが使うか
- **バックアップ**：楽屋シリーズとバミリ・ドリルボードのデータ（楽器台帳の写真も）を1つのファイルにまとめ、戻せます。引き継ぎファイル（次の人へのメモつき）と、引き継ぎのしおりの印刷。保存している量（録音・楽譜のPDFの「ファイル置き場」も）が出ます。ファイル置き場の録音・PDFは大きいので、このバックアップには入りません（楽譜ライブラリ・合奏ノートからzipで保存できます）
- **同期ファイル**：パソコンとスマホなど、同じ人が2つの端末で使うときに。片方で「同期ファイルを保存」、もう片方で「同期ファイルで合わせる」を押すと、ツールごと（楽屋のデータは団体の設定・部員・曲・楽器・本番ごと）に、新しく直したほうを残します。合わせる前に、何がどう変わるかを出し、どちらが新しいか分からないもの（バミリ・ドリルボードなど）は選べます。この端末の使い方（代表者・顧問用／部員用）は変えません。合わせたあとは「元に戻す」ができます
- **表示**：文字を大きくする（この端末の全部のツール）。ホーム画面に追加すると、どのツールから追加しても「楽屋」という1つのアプリになります

## しくみ

### 1つずつ独立している

全部のツールを、1つのリポジトリ `bamiriunei-arch.github.io` に入れています。フォルダ1つがツール1つです。
どのツールも、そのフォルダの `index.html` 1つで動き、ほかのフォルダのファイルを読み込みません（ホーム画面のアイコンだけは、楽屋のものを使います）。どれか1つを直しても、ほかに影響しません。
それぞれのフォルダに、説明書（`README.md`）・自動テスト（`tests/`）・ホーム画面用の設定とオフライン用の `sw.js` が入っています。自動テストは、GitHub に上げるたびに全ツール分が動きます。

### 共通部品

各 `index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分は、全ツールで同じ内容です（見た目と、データの読み書き・2つのタブの見張り・ファイル保存・印刷とPDF・CSV（Shift_JISも）・名簿の読み取り・パートの名前のそろえ方・見るだけのリンクとQRなど）。
1つのツールだけを直すときは、その外側だけを直します。共通部品を変えるときは、楽屋（`gakuya/index.html`）で直してから、リポジトリのいちばん上で `node sync-common.js` を動かすと、全ツールにそろえて写せます。変えたら `GKY.VERSION` を上げてください。

### 楽屋のデータ（全ツールで共有）

同じ場所に置いたツールは、ブラウザの `localStorage` の `gakuya.org` を共有します。中身はこの形です。

```json
{
  "app": "gakuya", "format": 1,
  "org": { "name": "団体の名前", "year": 2026, "type": "chu", "retire": "", "promoted": { "to": 2026, "at": "2026-04-01" },
           "role": "staff", "member": { "tools": ["gassou", "tempomap", "drillboard", "bamiri"], "concerts": true, "roster": false, "notes": true, "songs": false, "msg": "", "at": "" } },
  "members": [ { "id": "m…", "name": "山田 花子", "kana": "", "grade": "中2", "part": "Cl", "subs": ["B.Cl"], "status": "active", "active": true,
                 "roles": ["パートリーダー"], "joined": null, "note": "", "staffNote": "" } ],
  "songs": [ { "id": "s…", "title": "曲名", "kana": "", "composer": "", "arranger": "", "publisher": "", "dur": 360, "parts": ["Fl1", "Cl1", "Cl1"], "opt": ["Ob"] } ],
  "instruments": [ { "id": "g…", "no": "Cl-01", "name": "B♭クラリネット", "part": "Cl", "owner": "学校", "state": "使える", "user": "山田 花子", "usable": true } ],
  "concerts": [ { "id": "c…", "title": "第13回 定期演奏会", "date": "2027-03-20", "start": "14:00", "venue": "市民会館", "kind": "concert", "note": "", "hide": false,
                  "day": { "meet": "09:00", "meetPlace": "市民会館 楽屋口", "end": "17:30", "endPlace": "学校", "tt": [["9:00", "集合・楽器の搬入"]], "items": ["楽器", "楽譜"],
                           "dress": "制服", "jobs": [["受付", "1年 山田・佐藤"]], "memo": "", "contact": "顧問 鈴木", "at": "2026-10-11" } } ],
  "updated": { "org": 0, "members": 0, "songs": 0, "instruments": 0, "concerts": 0 }
}
```

- `org.type`：`chu` 中学校・`koko` 高校・`chuko` 中高一貫・`daigaku` 大学・`ippan` 一般・`chiiki` 地域クラブ（空は「まだ選んでいない」）。`retire` は大学の引退の時期（`大3`・`大4`）。`promoted` は最後に進級させた年度
- `members[].status`：`active` 在籍・`semi` 仮引退・`leave` 休部（休団）・`retired` 引退・`extra` エキストラ・`support` 賛助・OB/OG・`gone` 卒業・退部。`active`（true/false）は、演奏する人（在籍・エキストラ・賛助）かどうかで、前の版のツールのために残しています。仮引退の人は、コウバン・出欠で「入れる」と決めたときだけ候補に入ります
- `org.role`：この端末の使い方（`staff` 代表者・顧問用／`member` 部員用）。`org.member` は部員用の端末で使うツール（`tools`）とできること。部員用の設定リンク（`#join=…`）で入ります
- `concerts`：楽屋の本番。`kind` は `concert` 演奏会・`contest` コンクール・大会・`event` 依頼演奏・イベント・`school` 学校・地域の行事・`other` その他。`hide` は部員に見せない本番。ほかのツールの記録（本番逆算の本番・コウバンの演奏会・楽譜ライブラリの曲目一覧・仕込み図・搬入出リスト・出欠の本番の予定・会計の予算）は、`concert` に本番の `id` を持ってつながります（持っていなければ、同じ日付の本番が1つだけのとき、それとみます）。`day` は当日の案内（入れたときだけ。`tt` は [時刻, すること]、`jobs` は [係, だれ] の組）
- `members[].joined` は入団（入部）した年、`staffNote` は顧問・指導者だけのメモ（ファイルに入れるかどうかを選べます）
- `songs[].opt` は「なくても演奏できる」パート
- `members` は楽屋と、楽器決め（新入部員と決まった楽器）・コウバン（コウバンで足した・直した部員）が書きます。`songs` は楽譜ライブラリ、`instruments` は楽器台帳、`concerts` は楽屋（とほかのツールの「＋ 楽屋の本番の一覧に入れる」）が書きます。ほかのツールは読むだけです。書くツールは、自分の区分だけを書きかえます。部員用の端末では、楽屋のほかのツールからは書きかえません

パートは、バミリの奏者ラベルと同じ書き方（`Fl`・`Cl1`・`A.Sax`・`Tp`・`Hn`・`Euph`・`Tuba`・`S.D.`・`Timp` など）にそろえています。「クラリネット」「ラッパ」「パーカス」「コンバス」なども読み込むときに記号に直します。

### ファイル・リンクでのつながり

- ステマネの演奏会 → コウバン（曲の順番）、仕込み図（きっかけ表）、楽譜ライブラリ（演奏の記録・曲目一覧）。同じ場所ならこの端末のステマネから選べます（`GKY.pickStagemane`）。書き出したファイル（`{"app":"stagemane","concert":{…}}`）からも
- バミリで保存した配置図のファイル（`{"W":…,"D":…,"items":[…]}`）→ コウバン（席に名前を入れて返す）、仕込み図（下絵）、搬入出リスト（運ぶもの）
- テンポマップの共有コード（`TMZ…`）→ 合奏ノート（小節の目印。くり返し・D.S. も）
- テンポマップの録音 → 合奏ノート（`#media=…` で開く。クリックつきなら小節の目印を自動で）・ドリルボード（音源）
- 楽屋の本番から開く（アドレスの `#concert=…`）：本番逆算・コウバン・楽譜ライブラリ・ステマネ・仕込み図・搬入出リスト・出欠・練習計画・会計
- 出欠 → コウバン（休み）・合奏ノート（その日の欠席・遅刻）。楽器台帳の修理代 → 会計（帳簿）。楽譜ライブラリの曲目一覧 → コウバン（曲と受け持ち）
- 見るだけのリンク（アドレスの `#v=…`）：楽屋（本番の予定・当日の案内・お知らせ）・コウバン・搬入出リスト・本番逆算・出欠・練習計画・合奏ノート（コメント）。中身はリンクの中だけにあり、どこのサーバーにも送られません
- 部員用の設定リンク（`#join=…`、楽屋）と、合奏ノートの提出のリンク（`#n=…`。ノートと個人練習）も、中身はリンクの中だけにあります
- 同期ファイル（`{"app":"gakuya-sync","keys":{…},"mtimes":{…}}`）：同じ人の2つの端末を、キーごと（`gakuya.org` は区分ごとに `updated` で）新しいほうに合わせます

### Claude の画面の中で開いたとき

Claude のアーティファクトとして開いたときは、ツールごとに別の場所として開くので、楽屋のデータは共有されません。ファイルの保存は確認の画面を通り、印刷は「PDFで保存」になります。ふだん使うときは、公開ページで開いてください。

## GitHub Pages への置き方（はじめの1回）

（楽屋の画面の「置き方」のタブはなくしました。手順はここに書いておきます。）

1. GitHub（bamiriunei-arch）で「New repository」を押し、名前を `bamiriunei-arch.github.io`（このとおり）にして、**Public** で作ります
2. 「uploading an existing file」を押し、配ったフォルダの中身を入れて「Commit changes」。1回に上げられるのは100ファイルまでなので、ツールのフォルダをいくつかずつに分けて上げます
3. 自動テストの設定 `.github/workflows/test.yml` は、「Add file」→「Create new file」で名前に `.github/workflows/test.yml` と入れ、中身を貼って作るのが確実です（フォルダの名前が `.` で始まるため、画面から上げると入らないことがあります）
4. 「Settings」→「Pages」で、Branch が `main`・フォルダが `/ (root)` になっているか確かめます
5. 数分すると `https://bamiriunei-arch.github.io/gakuya/` で楽屋が開けます。「Actions」タブで「自動テスト」に緑のチェック（✓）が付けば、正しく動いています

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「まとめてバックアップ」で保存してください（最後に保存してから日がたつと、ツールの画面でお知らせします）。学校のChromebook・iPadは、サインアウトでデータが消える設定のこともあります。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器・本番のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `gakuya.` で始まります。
- 録音・楽譜のPDFは、端末の中の「ファイル置き場」（IndexedDB の `gakuya-media`）に入ります。こちらもどこのサーバーにも送られません。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ホーム画面に追加したとき・ネットがないときに開けるようにする |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「楽屋だけの見た目」「楽屋本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `gakuya/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/gakuya/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `gakuya` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js gakuya
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）、`tests/standalone.spec.js` がホーム画面のアプリの中での動き、`tests/v5.spec.js` が本番の一覧・まとめて足す／変える・仮引退・部員用の設定リンク・アンケートのテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
