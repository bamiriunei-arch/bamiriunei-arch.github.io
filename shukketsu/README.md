# 出欠

練習・本番ごとの出欠（出席・欠席・遅刻・早退と理由）を記録するツールです。
`index.html` 1つで動き、データは使う人のブラウザの中に保存されます。

公開ページ：https://bamiriunei-arch.github.io/shukketsu/

## できること

- **予定**：練習・合奏・本番などの予定（日付・時刻・場所・メモ）。「毎週くり返して足す」で、曜日と期間を選んで何回分もまとめて足せます（祝日をのぞける）
- **出欠**：予定ごとに、名簿の人を パート順に ○（出席）・遅（遅刻）・早（早退）・×（欠席）で入れ、理由も書けます。「未記入の人を全員出席にする」もあります
- **だれもいないパート**：全員が欠席のパートを赤で知らせます（まだ返事のない人がいるときは「かもしれない」として出します）
- **出席率**：人ごと・パートごと（今年度・今月・先月・この30日・全部、本番だけ）。出席率＝（出席＋遅刻＋早退）÷ 出欠を入れた回数
- **見るだけのリンク・QR と返事**：これからの予定をリンクで配り、受け取った人が自分の出欠を入れて「返事をコピー」→ LINE などで送る → 届いた返事を貼り付けると、出欠に入ります（サーバーなしで返事を集めるしくみ。返事の最後の `SK1|…` の行を読みます）
- **印刷**：記入用の出欠表（名前×その月の予定）、出欠の記録（○×と理由）、出席率の表。CSV・ファイルにも保存できます

## ほかのツールとのつながり

- 名簿は、楽屋の部員（在籍。設定でエキストラ・賛助・休部の人も）を使います。楽屋に名前がない人は「この出欠だけの名簿」に足せます
- 本番逆算スケジュールのひな形（合宿など）から開けます

## データの保存について

- 入力した内容は、使う人の端末のブラウザの中だけに保存されます。どこのサーバーにも送られません。AIも使っていません。
- ブラウザの履歴やサイトのデータを消すと、保存した内容も消えます。ときどき「ファイルに保存」か、楽屋の「まとめてバックアップ」で保存してください。
- 同じ場所（`bamiriunei-arch.github.io`）に置いたツールどうしは、楽屋に入れた部員・曲・楽器のデータを共有します（キー：`gakuya.org`）。このツール自身のデータのキーは `shukketsu.` で始まります。
- 出欠は、名前（空白をのぞいたもの）でつないでいます。楽屋で名前を直すと、前の出欠とはつながらなくなります。
- 見るだけのリンクで出欠を入れても、受け取った人の端末には保存されません。
- 同じツールを2つのタブで開いて直したときは、あとから保存する方で「どちらを残すか」を聞きます（黙って上書きしません）。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（これだけで動きます） |
| `sw.js`・`manifest.webmanifest`・`icon-*.png`・`apple-touch-icon.png` | ネットがないときに開けるようにする。ホーム画面に追加すると「楽屋」のアプリになります（アイコンは楽屋のもの） |
| `tests/` | 自動テスト（アプリが壊れていないか調べる） |
| `playwright.config.js` | 自動テストの設定 |

アプリの版と更新内容は `index.html` の中の `APP_VERSION` と `CHANGELOG` にあります（画面左上の名前を押すと見られます）。

## 共通部品について

`index.html` の中の「楽屋シリーズ 共通部品 ここから〜ここまで」の部分（見た目とその下のしくみ）は、楽屋シリーズの全ツールで同じ内容です。
このツールだけを直すときは、その外側（「出欠だけの見た目」「出欠本体」）を直してください。
共通部品を変えるときは、全ツールで同じに変えて、`GKY.VERSION` を上げてください。

## 更新のしかた

このフォルダは、GitHub のリポジトリ `bamiriunei-arch.github.io` の中の `shukketsu/` フォルダです（公開ページ：https://bamiriunei-arch.github.io/shukketsu/）。

1. GitHub でリポジトリ `bamiriunei-arch.github.io` の `shukketsu` フォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上げて「Commit changes」
2. 数分すると公開ページが新しくなります
3. リポジトリの「Actions」タブで、自動テストが緑のチェック（✓）になっているか見ます
   - 赤い × のときは、押すとどのテストが失敗したか見られます

## 自動テスト（なくても大丈夫です）

Node.js（20以上）と Python 3 が入っていれば、リポジトリのいちばん上で：

```
npm install
npx playwright install chromium
node test-all.js shukketsu
```

`tests/app.spec.js` がパソコンの幅、`tests/phone.spec.js` がスマホの幅（390px）のテストです。
テストでは `index.html?test` のようにアドレスに `?test` を付けて開き、アプリの中身を `window.__app` から触っています。ふだんの使い方（`?test` なし）では何も変わりません。
